# M1: live feasibility gate (`pnpm gate`) and D3 decision

## What / why
- `scripts/gate.ts` (`pnpm gate`, or `pnpm gate <substring>` for one site): starts its own production app (:3200, harness on) and proxy (:8789, real DNS, `ENVIRONMENT=development`, so fixture hosts are off). For each site in `docs/test-portfolios.json` it resolves redirects (≤5 hops, each re-validated), runs the proxy `/__health` check, then Playwright on chromium + WebKit iPhone 14: render → scripted interaction (scroll, hover + click a visible link to another page / in-page link / menu button → DOM or URL change) → tap produces an anchor → reload → re-anchor succeeds. Non-blocking; not part of `pnpm verify`.
- `packages/shared/src/redirects.ts`: `resolveSiteUrl()` follows redirects safely; review creation (M4) reuses it.
- Outputs: `docs/PLATFORM_SUPPORT.md` (report), `docs/gate-results.json` (raw), `apps/web/lib/platform-policy.json` (D3 policy read by the health check).

## Result (2026-11-03)
- 15/15 reachable; **12 pass on both browsers = 80%** (threshold 70%). Framer 3, Webflow 3 (need ≥2 each). **Gate PASS → live mode is the default for all platforms**; `screenshotPlatforms` is empty.
- Failures (interaction step only; render, tap → anchor and re-anchor passed): niklasbubori.com (Webflow), brittanychiang.com (Next), thaisafernandes.com (chromium only).
- Transparency: the first run reported 60%. The probe was clicking logo links back to the same page and couldn't see mobile nav hidden behind a menu button, and a tsx `__name` helper broke the in-page probe. Those were bugs in the new gate script, fixed before recording results; no threshold or check was relaxed.

## Acceptance covered

## Known limitations
- The per-review headless health check (M4) confirms render + `overlay:ready`, not interactions, so a site like the three above would open live with some interactions not responding. Screenshot mode remains the automatic fallback when the headless check fails.
- "Nightly" runs: Phase A has no CI, so the gate is run manually (`pnpm gate`). Phase B adds a scheduled GitHub Action.
- Results depend on third-party sites on the run date.
