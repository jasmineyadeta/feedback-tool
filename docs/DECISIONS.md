# Decision Log

Source of truth for every product/architecture fork. **The coding agent must not change any decision here.** If a decision blocks progress, add an entry to `docs/NEEDS_HUMAN.md` (see CLAUDE.md → Stop conditions) and continue with unblocked work.

Legend: **[J]** decided by Jas · **[C]** defaulted by Claude during spec review — Jas may override; until then treat as decided.

**Phases.** **Phase A — local POC (now):** everything runs on Jas's Mac, no accounts, $0. **Phase B — cloud pilot (later):** the same code deployed to free cloud services. Phase B must be configuration + small adapters only, never a rebuild (D30).

| # | Area | Decision | Why |
|---|---|---|---|
| D1 | Website rendering | **[J] Live, interactive rendering via a document proxy + injected overlay script.** Only the HTML document is proxied; the site's own JS/CSS/images load from their original hosts. | Designers' interactive work must survive; snapshots lose it. Pattern proven by Pastel, MarkUp, Hypothesis Via. |
| D2 | Fallback | **[C] Automatic "Screenshot mode"** for sites that fail the proxy health check: full-page screenshot(s) with coordinate pins + text map. Clearly labelled to reviewer and candidate. Never silent. | Agent never blocks on a site failing. |
| D3 | Feasibility gate | **[C]** Pass = ≥70% of reachable test sites render with interactions working AND accept tap + AI anchors, on Chromium and WebKit (iPhone emulation); must include ≥2 Framer and ≥2 Webflow passes. Below threshold → ship Screenshot mode for failing platforms and continue. | Removes the human-judgment stop from the original PRD. |
| D4 | Build order | **[J] PDF end-to-end first**, website proxy gate in parallel. | Fully supported path exists regardless of proxy outcome. |
| D5 | Reviewer model | **[J] One link per reviewer.** Candidate creates a reviewer invite (optional name hint) → unique link. Per-reviewer revoke and attribution. Multiple reviewers per artifact. | Matches multi-perspective business case. |
| D6 | Owner auth | **[J] Email magic link** (Supabase Auth). | Real ownership, cross-device, gives notification email. |
| D7 | Reviewer identity | **[J] Name + email collected at submit**, prefilled from candidate's name hint. No reviewer account. Displayed as "self-reported". | Zero friction to start. |
| D8 | Commenting model | **[J] Talk-through: recording = comment mode.** While recording, site interactions are paused and taps mark anchors. Speech is split into comments. **AI infers anchors for untapped speech; taps always override AI.** Typed single comments also available. | Ease is the mass-appeal; tap gives precision. |
| D9 | AI anchor safety | **[J/C]** AI only (a) splits transcript into **verbatim contiguous spans** and (b) picks an anchor from elements actually visible at that time. Code verifies spans reconstruct the transcript exactly; any mismatch → reject AI output, fall back to tap/viewport anchors. Confidence < 0.6 → viewport anchor. | Preserves "never alter reviewer meaning". |
| D10 | Post-recording UX | **[J] Split preview + one-tap "Looks good".** Reviewer can tap any comment to edit text or re-anchor. | ~5s when AI is right. |
| D11 | AI label | **[J] Candidate sees subtle "auto-placed" label** on AI anchors; can re-anchor. | Honesty about AI. |
| D12 | Browse vs comment | **[C]** Not recording = site behaves normally (browse). Recording = taps anchor, site clicks suppressed. Plus a "Type a comment" button that enters one-shot tap-to-anchor. | Falls out of D8. |
| D13 | Audio | **[J] Keep for playback 90 days**, then auto-delete; deleted immediately on review/invite deletion. Disclosed to reviewer before first recording. | Tone is value; bounded retention. |
| D14 | Transcription | **[J] Phase A: local `whisper.cpp` server** (Homebrew `whisper-cpp`, model `large-v3-turbo`; fall back to `small`/`base` if too slow on the machine), audio normalized to 16 kHz WAV with `ffmpeg`, behind a `Transcriber` interface. Must return word-level start/end (whisper.cpp max-segment-length 1 / split-on-word); if the spike shows unusable word timing, use `faster-whisper` (`word_timestamps=True`) in a tiny local Python service instead — no human needed. **Phase B:** Cloudflare Workers AI Whisper adapter (free tier), Groq as backup. | $0, private (audio never leaves the Mac), same interface later. |
| D15 | Segmentation/anchor LLM | **[J/C] Phase A: local Ollama** model with JSON-schema structured output, model id in env `ANCHOR_MODEL`, behind `AnchorResolver`. Agent picks the strongest model that runs acceptably on the Mac (target ≤15 s per resolution) and passes the resolver eval (≥80% correct anchors, SPEC §5.2). **Phase B:** Cloudflare Workers AI adapter. Validator protects against bad output regardless. | $0, private, swappable. |
| D16 | Stack | **[J/C]** Next.js (App Router, TypeScript) + **Supabase** (Postgres, Storage, Auth) + **Cloudflare Worker** proxy. **Phase A:** Supabase CLI in Docker (incl. local email inbox), `wrangler dev` (local, no Cloudflare login), local Playwright for screenshots, all started by `pnpm dev`. **Phase B:** Vercel Hobby, Supabase free cloud, Worker on Cloudflare, Browser Run screenshots, Resend email. | Identical stack in both phases → no rebuild. |
| D17 | Origin isolation | **[C] Proxied content is never served from the app origin.** Phase A: app on `localhost:3000`, proxy on `localhost:8787` (different origin); on phone, separate tunnel hostnames. Phase B: per-review subdomains `{rid}.view.{DOMAIN}` (path-preserving, required for SPA routers; SPEC §6). App embeds the proxy in an iframe; communication only via `postMessage` with origin checks. | Third-party JS runs under our roof. |
| D18 | Proxy abuse | **[C]** Worker only serves URLs carrying an app-issued HMAC-signed, expiring token bound to a review's registrable domain (eTLD+1). GET/HEAD only. Strips `Set-Cookie`, CSP, X-Frame-Options from document responses. Blocks private/loopback/link-local IPs and non-https. Navigation outside the eTLD+1 opens a new tab unproxied with a notice. Forms blocked. Service-worker registration blocked. | Not an open proxy; SSRF-safe. |
| D19 | MVP extras | **[J] IN:** email to candidate on submit; multi-page navigation within a site; candidate "mark addressed". **OUT:** follow-up review/versioning, multi-reviewer synthesis, payments, analytics vendors. | |
